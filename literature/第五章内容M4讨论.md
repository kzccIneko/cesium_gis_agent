# 2. 我建议给M4设置明确的“进入条件”

不要再用类似：

> $\rho>0.3$ 就算有效。

这种人为阈值。

建议至少检查四件事：

| 条件 | 怎么量化 |
|---|---|
| 数据覆盖 | 候选交互组合是否分布在多个独立路线/日期，而不是集中于一个局部路段 |
| 重复性 | 不同分组测试中残差偏差方向是否一致 |
| 预测增益 | 加入交互项后，独立测试集MAE/RMSE下降多少，置信区间是否支持真实改善 |
| 复杂度代价 | 增加多少参数才得到上述提升，避免用大量交互项换很小的误差下降 |

因此M4不是：

```text
一定存在的第四模型
```

而是：

```text
残差诊断
→ 找到稳定缺陷
→ 才建立针对性的修正模型
```

我认为这个逻辑比DS的“全部放未来工作”更强，也比我们前面“提前设计M4”更严谨。

## 3. 土壤模块和M4不是竞争关系

这里我想特别说明：**土壤模块没有被替代。**

根据原始对话记录，土壤部分早期就是一个重要的方法子任务，包括公开土壤属性、湿润状态、CI或承载能力估计，以及进入车辆通行模型的完整链条；当时甚至被定位为较大的工作量组成。

现在只是需要把原来的确定性表达修正：

### 原来过于简单的想法

```text
SoilGrids
+
TWI
↓
唯一CI值
```

### 现在更合理

```text
土壤质地、容重等
+
湿润状态
+
必要的环境协变量
↓
土壤机械状态估计
↓
强度范围/情景范围
↓
与车辆软土能力比较
↓
土壤风险
```

已有实测研究表明，CI与含水状态、容重、黏粒等变量有关，而且这些关系会随深度和土壤状态改变，因此从公开属性直接得到一个唯一CI值确实过于乐观。([科学直接](https://www.sciencedirect.com/science/article/abs/pii/S0167198713000020?utm_source=chatgpt.com))

但还要纠正DS的一点：

> **没有经过统计校准时，不要轻易称为“概率CI区间”或“置信区间”。**

更诚实的名称可以是：

- 参数不确定性范围；
- 情景区间；
- 土壤强度估计范围。

只有建立了统计模型并检验区间覆盖率以后，才适合说概率意义上的区间。

所以我目前认为论文中的两个有潜力的方法方向应该是：

```text
方法方向A
土壤机械状态估计
+
不确定性向车辆风险传播

方法方向B
物理风险模型
+
实车残差诊断
+
有证据时进行稀疏交互修正
```

这两个不是互相替代，而是不同层级：

```text
环境状态估计
     ↓
单因素车辆风险
     ↓
基础融合模型
     ↓
实车残差诊断
     ↓
必要时交互修正
     ↓
路径规划
```
