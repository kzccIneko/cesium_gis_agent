# 云端 GPU 训练操作清单

> 目的：在云端训出 Qwen3.5-4B 的意图路由 LoRA adapter（本机 6 GB 显存贴线跑满，不适合做正式训练）。
> 全部步骤约 20 分钟，花费约 **0.6 元**。产物只有几十 MB，下载回本机即可用。

---

## 〇、先明确三件事

| 问题 | 答案 |
|---|---|
| 训练效果和显卡有关吗？ | **无关**。显卡只决定跑多快、能不能跑得动。效果取决于数据与超参。 |
| 训练产物通用吗？ | **通用**。adapter 是"补丁"，与用哪张卡训的无关，下载回本机直接给 llama.cpp 用。 |
| 为什么不在本机训？ | 4B 的 QLoRA 实测峰值 6.04 GB，而本机卡只有 6.00 GB —— 零余量，且笔记本降频会崩（实测功耗墙 75W→47W）。 |

---

## 一、选平台与实例

推荐 **AutoDL**（垂直算力平台，便宜、上手快）。

| 显卡 | 显存 | 参考价格 | 本次训练预计耗时 | 预计花费 |
|---|---|---|---|---|
| RTX 3080 Ti | 12 GB | ¥1.6/时 | 8–12 分钟 | ~¥0.3 |
| RTX 3090 | 24 GB | ¥1.9/时 | 8–12 分钟 | ~¥0.4 |
| **RTX 4090** | **24 GB** | **¥2.2/时** | **4–8 分钟** | **~¥0.6** |

> 价格随行情浮动，以控制台实时显示为准。**任意 ≥12 GB 的卡都够用**（脚本会自动按显存切 4-bit）。

**务必避开**：阿里云「百炼」这类**一键微调**产品 —— 训完的模型留在云上拿不回来，与本项目"模型属于自己系统"的定位冲突。
要选 **PAI-DSW** 这种"给你一台带显卡的机器"的形态。

## 二、创建实例（网页操作，约 3 分钟）

1. 注册 → **实名认证** → 充值（10 元起）
2. 进入「算力市场」，筛选：
   - **GPU**：RTX 4090（或 3090 / 3080Ti）
   - **镜像**：选 `PyTorch` 分类下的 **PyTorch 2.x + CUDA 12**（框架已预装，省一步）
   - **计费**：按量计费
3. 创建并开机（约 1 分钟）

> 数据盘/系统盘默认即可。本任务的模型缓存约 9 GB，注意别选太小的盘。

---

## 三、上传代码与数据（约 2 分钟）

只有 **700 KB** 需要上传，直接在 JupyterLab 里拖拽即可。

1. 打开实例的 **JupyterLab**（控制台上有入口）
2. 在左侧文件树里新建目录 `bench/`
3. 从本机把下面这些文件拖进去（保持相对路径）：

```
bench/
├── cloud_train.sh          ← 一键脚本
├── train_intent_lora.py    ← 训练脚本
├── build_sft_data.py       ← 数据构造（可选，数据已在 sft_data/ 里）
└── sft_data/
    ├── train.json          ← 720 条训练样本
    └── eval.json           ← 80 条留出集
```

> 本机路径：`D:\VS_Code_Program\CesiumJS_Debug\bench\`

---

## 四、跑训练（一条命令）

在 JupyterLab 里开一个 **Terminal**，执行：

```bash
cd bench
bash cloud_train.sh
```

脚本会自动完成 5 步，**不需要人工干预**：

| 步骤 | 做什么 | 耗时 |
|---|---|---|
| 0 | 自检 GPU 与 CUDA 是否可用 | 秒级 |
| 1 | 装 transformers / peft / bitsandbytes 等 | 1–2 分钟 |
| 2 | 从 ModelScope 下 Qwen3.5-4B（约 8.8 GB） | 2–4 分钟 |
| 3 | 校验训练数据完整性 | 秒级 |
| 4 | **训练**（会自动先测基线 → 训练 → 再测一遍） | 4–12 分钟 |
| 5 | 打包产物 | 秒级 |

**脚本内置的贴心处理**：

- 显存 < 16 GB 时**自动启用 4-bit（QLoRA）**，避免 OOM 白跑
- 训练前后**各测一次留出集**，直接产出对比数字，不需要你另外跑评测
- 缺数据文件会立刻报错退出，不会跑到一半才失败

**你会在终端里看到**（示意）：

```
  检测到 24 GB 显存 → 使用 bf16 加载
  线性层数: 187
  trainable params: 10,822,656 || all params: 4,024,zzz,zzz || trainable%: 1.42
[基线] 训练前的意图准确率…
  训练前: 57.5%  (46/80)
[训练] 2 epoch, lr=0.0002, r=16
  ...
[评测] 训练后的意图准确率…
  训练后: 97.5%  (78/80)
```

> **「训练前 57.5% → 训练后 97.5%」这组数字就是这次实验的结论**，脚本会自动写进产物里的 `eval_result.json`。

## 四·五、或者：交给 AI 远程接管（可选）

如果不想自己敲命令，本仓库已备好远程控制脚本 `bench/cloud_remote.py`，
可由 AI 一条命令走完「上传 → 训练 → 取回产物」。

**你只需在控制台的「SSH 登录指令」里找到三个信息**：主机地址、端口、密码。

然后 AI 执行：

```bash
export CLOUD_SSH_PASSWORD='<你的密码>'
python bench/cloud_remote.py --host <主机> --port <端口> --action all
```

也可以分步：`--action upload` / `train` / `fetch`。

**能力边界（先讲清楚）**：

| 能远程做 | 必须你自己做 |
|---|---|
| 上传代码与数据（SFTP） | 注册账号、实名认证 |
| 装依赖、从 ModelScope 下模型 | 充值、支付 |
| 启动训练并实时回传终端输出 | 在网页上点「开机」 |
| 把 adapter 打包下载回本机 | 到控制台确认【关机】 |

> **安全提醒**：把 SSH 密码给出，等于给出那台实例的完全控制权。它只用于这次训练，
> 但你应当知情 —— 训练结束后建议到控制台**重置实例密码**或直接释放实例。
> 不放心的话走上面的手动流程，效果完全相同，只是要自己粘贴命令。

## 五、取回结果（约 1 分钟）

产物 `bench/geoagent_lora.tar.gz` 只有几十 MB。


## 六、⚠ 关机（最重要的一步）

**训练一结束立刻回控制台关机**（不是"关闭浏览器标签页"）。按量计费按开机时长算，忘了关会一直扣钱。

AutoDL 的关机**保留数据盘**，下次开机环境还在，不用重装。

---

## 七、常见问题

| 现象 | 原因与处理 |
|---|---|
| `❌ 未找到 nvidia-smi` | 实例没挂到 GPU，或选错了镜像。回控制台确认。 |
| `❌ torch 能看到但 CUDA 不可用` | 镜像装的是 CPU 版 torch。执行 `pip install torch --index-url https://download.pytorch.org/whl/cu121` 重装。 |
| `❌ 缺 sft_data/train.json` | 只传了脚本没传数据。回第三步把 `sft_data/` 一起拖上去。 |
| 模型下载卡住 | ModelScope 偶尔波动，重跑 `bash cloud_train.sh` 即可（已下载的部分会跳过）。 |
| `CUDA out of memory` | 脚本已按显存自动切 4-bit；若仍 OOM，把脚本里的 `--accum 8` 改成 `16`、或减小 `--max-len`。 |
| 训练完忘了关机 | 立刻关。数据盘保留，下次接着用。 |

## 八、训完回本机之后

adapter 拉回来放在 `bench/lora_out/intent_4b/`，本机要做两件事：

1. **合并权重**：把 adapter 合并回底座，再转成 GGUF，供 llama.cpp 使用（合并后约 8 GB → 量化后约 2.6 GB）
2. **接入推理链路**：把意图分类的调用从"底座 + 提示词"切到"微调后的模型"

> 这两步在本机做（CPU 合并即可，不需要 GPU）。做完后再跑一次 v20 评测，与现在的 v19（主集 98.75%）对比，即可知道微调对**端到端指标**的实际贡献。
