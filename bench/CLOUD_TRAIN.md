# 云端 GPU 训练操作清单

> 目的：在云端训出 Qwen3.5-4B 的意图路由 LoRA adapter（本机 6 GB 显存贴线跑满，不适合做正式训练）。
> 全部步骤约 20 分钟，花费约 **0.6 元**。产物只有几十 MB，下载回本机即可用。

---

## 〇、先明确三件事

| 问题 | 答案 |
|---|---|
| 训练效果和显卡有关吗？ | **无关**。显卡只决定跑多快、能不能跑得动。效果取决于数据与超参。 |
| 训练产物通用吗？ | **通用**。adapter 是"补丁"，与用哪张卡训的无关，下载回本机直接给 llama.cpp 用。 |
| 为什么不在本机训？ | 4B 的 QLoRA 实测峰值 6.04 GB，而本机卡只有 6.00 GB —— 零余量，且笔记本降频会崩（实测功耗墙 75W→47W）。 |

---

## 一、选平台与实例

推荐 **AutoDL**（垂直算力平台，便宜、上手快）。

| 显卡 | 显存 | 参考价格 | 本次训练预计耗时 | 预计花费 |
|---|---|---|---|---|
| RTX 3080 Ti | 12 GB | ¥1.6/时 | 8–12 分钟 | ~¥0.3 |
| RTX 3090 | 24 GB | ¥1.9/时 | 8–12 分钟 | ~¥0.4 |
| **RTX 4090** | **24 GB** | **¥2.2/时** | **4–8 分钟** | **~¥0.6** |

> 价格随行情浮动，以控制台实时显示为准。**任意 ≥12 GB 的卡都够用**（脚本会自动按显存切 4-bit）。

**务必避开**：阿里云「百炼」这类**一键微调**产品 —— 训完的模型留在云上拿不回来，与本项目"模型属于自己系统"的定位冲突。
要选 **PAI-DSW** 这种"给你一台带显卡的机器"的形态。

## 二、创建实例 —— 逐项怎么选（对着创建页面）

### 页面字段逐项对照

| 页面上的项 | 怎么选 | 为什么 |
|---|---|---|
| **计费方式** | **按量计费** | 我们只跑一次、约 20 分钟。包日/包周适合长期用，本次用不上 |
| **主机** | 选 **RTX 4090 24GB**（¥2.18/时） | 24 GB 显存训 4B 很宽裕，且 4090 算力高、跑得最快。若 4090 无库存，选 3090（¥1.9）或 3080Ti（¥1.6）也够 |
| 　└ 库存列（如 `0/8`） | 数字表示"空闲卡数 / 总卡数" | `0/8` = 8 张全空闲，可以租 |
| **GPU 数量** | **1** | 我们只训一个小模型，多卡是浪费钱（价格按卡数翻倍）。多卡只在训练大模型、单卡装不下时才需要 |
| **数据盘** | 默认（免费 50 GB） | 够用：模型缓存 8.8 GB + 训练环境约 5 GB。不够可以之后扩容 |
| **系统盘** | 默认即可（表中约 30–50 GB） | 存系统和 Python 环境，默认值够 |
| **镜像** | 见下方专门说明 | ⚠ 这一项最容易选错 |
| **优惠券** | 有就选 | 无则跳过 |
| 底部 **创建并开机** | 最后点 | —— |

### 镜像怎么选（点开下拉后）

页面会显示「基础镜像 / 社区镜像 / 我的镜像」三个页签，选 **基础镜像**，
然后在框架下拉里选 **PyTorch**，接着会出现版本选择。

**推荐组合**：

```
框架   : PyTorch
版本   : 2.x（列表中最新或次新即可）
Python : 3.10 或 3.11      ← 不要选 3.12+
CUDA   : 12.1 或 12.4      ← 不要低于 11.8
```

**每项的理由**：

| 选项 | 为什么这么选 |
|---|---|
| **为什么选 PyTorch 镜像** | 它是"预装好深度学习框架"的镜像，省掉自己编译安装的麻烦。如果选 Miniconda，你还要自己装 PyTorch（约 2.6 GB，正是我们本机被卡住的那一步） |
| **为什么 Python 要 3.10 / 3.11** | 我们要装的 `transformers` 5.x 需要 Python ≥3.9；3.12 以上有些依赖还没跟上，容易在装包环节翻车 |
| **为什么 CUDA 要 ≥11.8** | 4-bit 量化训练依赖的 `bitsandbytes` 库，官方要求 CUDA 11.8 以上 |
| **不用管主机的"CUDA 13.2"** | 那是**驱动**版本（装在你租的物理机上），镜像里的是**运行时**版本（装在容器里），两者独立，选镜像按上面来即可 |

> 选错的代价只是重建一次实例，不影响数据；但如果选成 Miniconda 又没装 CUDA 版 PyTorch，
> 会白花十几分钟在装包上，所以这一项值得认真选。

### 创建之后

1. 实例启动约 1 分钟
2. 在「控制台 → 容器实例」里能看到它
3. **点「SSH 登录指令」**，会显示类似这样一串：

```
ssh -p 38672 root@region-1.autodl.com
        ↑端口        ↑主机
```

密码在同一处（或创建实例时你设置的那个）。**主机、端口、密码这三个信息**，
后面无论是你自己操作还是交给我远程接管，都用得到。

> 本任务的模型缓存约 9 GB，注意别选太小的数据盘。

## 四、跑训练（一条命令）

在 JupyterLab 里开一个 **Terminal**，执行：

```bash
cd bench
bash cloud_train.sh
```

脚本会自动完成 5 步，**不需要人工干预**：

| 步骤 | 做什么 | 耗时 |
|---|---|---|
| 0 | 自检 GPU 与 CUDA 是否可用 | 秒级 |
| 1 | 装 transformers / peft / bitsandbytes 等 | 1–2 分钟 |
| 2 | 从 ModelScope 下 Qwen3.5-4B（约 8.8 GB） | 2–4 分钟 |
| 3 | 校验训练数据完整性 | 秒级 |
| 4 | **训练**（会自动先测基线 → 训练 → 再测一遍） | 4–12 分钟 |
| 5 | 打包产物 | 秒级 |

**脚本内置的贴心处理**：

- 显存 < 16 GB 时**自动启用 4-bit（QLoRA）**，避免 OOM 白跑
- 训练前后**各测一次留出集**，直接产出对比数字，不需要你另外跑评测
- 缺数据文件会立刻报错退出，不会跑到一半才失败

**你会在终端里看到**（示意）：

```
  检测到 24 GB 显存 → 使用 bf16 加载
  线性层数: 187
  trainable params: 10,822,656 || all params: 4,024,zzz,zzz || trainable%: 1.42
[基线] 训练前的意图准确率…
  训练前: 57.5%  (46/80)
[训练] 2 epoch, lr=0.0002, r=16
  ...
[评测] 训练后的意图准确率…
  训练后: 97.5%  (78/80)
```

> **「训练前 57.5% → 训练后 97.5%」这组数字就是这次实验的结论**，脚本会自动写进产物里的 `eval_result.json`。

## 四·五、或者：交给 AI 远程接管（可选）

如果不想自己敲命令，本仓库已备好远程控制脚本 `bench/cloud_remote.py`，
可由 AI 一条命令走完「上传 → 训练 → 取回产物」。

### 先配免密登录（一次配置，之后免密）

控制台 **设置 → SSH 免密登录 → 添加 SSH 公钥**，粘贴本机公钥：

```bash
cat ~/.ssh/id_ed25519.pub      # 复制输出的整行
```

> 控制台方式的好处是**持久**：实例重建、新开实例都会自动注入该公钥。
> 直接往实例的 `~/.ssh/authorized_keys` 写也生效，但实例重置镜像后会被清掉。

本机 `~/.ssh/config` 已加好别名（**端口是实例专属，重建后会变，需同步改这里**）：

```
Host autodl
    HostName <控制台给出的实例地址>
    Port <控制台给出的端口>
    User root
    IdentityFile ~/.ssh/id_ed25519
    IdentitiesOnly yes
```

验证与日常用法：

```bash
ssh autodl "nvidia-smi"                       # 免密执行命令
scp bench/train_intent_lora.py autodl:/root/autodl-tmp/   # 免密上传
scp autodl:/root/autodl-tmp/geoagent_lora.tar.gz .        # 免密取回
```

### 再让 AI 跑训练

```bash
python bench/cloud_remote.py --action all      # 串好别名后，无需再传 host/port/密码
```

也可以分步：`--action upload` / `train` / `fetch`。

> 若不配免密，仍可用密码方式：`export CLOUD_SSH_PASSWORD='<密码>'` 后
> `python bench/cloud_remote.py --host <主机> --port <端口> --action all`。

**能力边界（先讲清楚）**：

| 能远程做 | 必须你自己做 |
|---|---|
| 上传代码与数据（SFTP） | 注册账号、实名认证 |
| 装依赖、从 ModelScope 下模型 | 充值、支付 |
| 启动训练并实时回传终端输出 | 在网页上点「开机」 |
| 把 adapter 打包下载回本机 | 到控制台确认【关机】 |

> **安全提醒**：把 SSH 密码给出，等于给出那台实例的完全控制权。它只用于这次训练，
> 但你应当知情 —— 训练结束后建议到控制台**重置实例密码**或直接释放实例。
> 不放心的话走上面的手动流程，效果完全相同，只是要自己粘贴命令。

## 六、⚠ 关机（最重要的一步）

**训练一结束立刻回控制台关机**（不是"关闭浏览器标签页"）。按量计费按开机时长算，忘了关会一直扣钱。

## 七、常见问题

| 现象 | 原因与处理 |
|---|---|
| `❌ 未找到 nvidia-smi` | 实例没挂到 GPU，或选错了镜像。回控制台确认。 |
| `❌ torch 能看到但 CUDA 不可用` | 镜像装的是 CPU 版 torch。执行 `pip install torch --index-url https://download.pytorch.org/whl/cu121` 重装。 |
| `❌ 缺 sft_data/train.json` | 只传了脚本没传数据。回第三步把 `sft_data/` 一起拖上去。 |
| `python: command not found` | AutoDL 的 Miniconda **不在默认 PATH 里**（实测 `which python` 为空，只有 `/root/miniconda3/bin/python`）。用绝对路径，或先 `source /root/miniconda3/etc/profile.d/conda.sh && conda activate base`。脚本里若直接写 `python` 会在此翻车。 |
| 模型下载卡住 | ModelScope 偶尔波动，重跑 `bash cloud_train.sh` 即可（已下载的部分会跳过）。 |
| `CUDA out of memory` | 脚本已按显存自动切 4-bit；若仍 OOM，把脚本里的 `--accum 8` 改成 `16`、或减小 `--max-len`。 |
| 训练完忘了关机 | 立刻关。数据盘保留，下次接着用。 |

## 八、训完回本机之后

adapter 拉回来放在 `bench/lora_out/intent_4b/`，本机要做两件事：

1. **合并权重**：把 adapter 合并回底座，再转成 GGUF，供 llama.cpp 使用（合并后约 8 GB → 量化后约 2.6 GB）
2. **接入推理链路**：把意图分类的调用从"底座 + 提示词"切到"微调后的模型"

> 这两步在本机做（CPU 合并即可，不需要 GPU）。做完后再跑一次 v20 评测，与现在的 v19（主集 98.75%）对比，即可知道微调对**端到端指标**的实际贡献。
